# GM 연결 (호스트 Codex GM + 원격 동시 접속)

Status: ready-for-agent

관련 대전제: 2.1, 2.2, 2.4, 2.5, 8.5, 8.6, 9장

## Problem Statement

지금 플레이 화면은 엔진과 연결돼 이동은 실제로 되지만, GM 자리는 가짜 문장("(가짜 GM) ...")이다. 플레이어가 행동을 적어도 아무도 서술하지 않고, 판정이 필요한 행동을 해석해 엔진 상태를 바꿔 줄 주체도 없다. 또 세션은 호스트 한 브라우저만 가정하고 있어서 친구들이 원격으로 같은 파티에 들어와 함께 플레이할 수 없다.

## Solution

호스트 PC에서 웹 서버(Next.js + 엔진)를 돌리고, 플레이어 행동이 들어오면 엔진이 호스트의 공식 `codex` CLI를 `codex exec`로 한 번 실행해 GM 턴을 진행한다. GM은 엔진이 연 MCP 도구로만 상태를 바꾸고, 마지막 응답을 서술로 로그에 남긴다.

원격 플레이어는 호스트가 연 터널 주소로 접속해 방 코드를 넣고 캐릭터를 고른다. 몇 초 안에 들어온 여러 플레이어의 행동은 하나로 묶어 GM 턴 한 번에 넘긴다. 모든 접속자의 화면은 서버가 밀어 주는 상태로 실시간 갱신된다.

지도 클릭·이동 버튼 같은 명확한 이동은 지금처럼 엔진이 바로 처리하고, 그 도착 이벤트를 GM 턴에 넘겨 도착 서술만 하게 한다 (대전제 8.6).

## User Stories

1. 플레이어로서, 행동을 적어 보내면 GM이 상황에 맞게 서술해 주길 원한다. 그래야 TRPG처럼 이야기가 진행된다.
2. 플레이어로서, GM이 서술하는 동안 "GM이 생각 중" 표시를 보고 싶다. 그래야 입력이 먹혔는지 안다.
3. 플레이어로서, GM이 "문이 열렸다"고 말하면 실제로 지도와 이동 목록에도 반영되길 원한다. 그래야 서술과 화면이 어긋나지 않는다.
4. 플레이어로서, "몰래 시장으로 간다"처럼 판정이 필요한 이동을 행동으로 적으면 GM이 판단해 파티를 옮겨 주길 원한다.
5. 플레이어로서, 이동 버튼이나 장면 지도를 누르면 기다리지 않고 바로 옮겨지고, 곧이어 GM의 도착 묘사를 보고 싶다.
6. 플레이어로서, 처음 방문한 지역에서는 자세한 묘사를, 다시 온 지역에서는 짧은 묘사를 받고 싶다.
7. 원격 플레이어로서, 호스트가 준 주소와 방 코드로 브라우저에서 바로 들어가고 싶다. 설치나 로그인은 원하지 않는다.
8. 원격 플레이어로서, 입장할 때 내 캐릭터를 고르고, 새로고침해도 같은 캐릭터로 남아 있길 원한다.
9. 원격 플레이어로서, 다른 플레이어의 행동과 GM 서술이 내 화면에도 바로 나타나길 원한다.
10. 원격 플레이어로서, 로그에서 어떤 행동을 누가(어느 캐릭터가) 했는지 알고 싶다.
11. 파티로서, 거의 동시에 보낸 여러 명의 행동이 한 장면으로 함께 서술되길 원한다. 그래야 번갈아 기다리는 느낌이 줄어든다.
12. 파티로서, GM 턴이 도는 동안 보낸 행동이 사라지지 않고 다음 턴에 반영되길 원한다.
13. 파티로서, GM이 우리 캐릭터의 행동이나 대사를 멋대로 정하지 않길 원한다 (대전제 9.2).
14. 파티로서, 섬의 비밀이 공개 조건 없이 튀어나오지 않길 원한다 (대전제 9.2).
15. 호스트로서, 내 `codex login` 한 번으로 GM을 돌리고 API 키는 쓰지 않길 원한다 (대전제 2.4).
16. 호스트로서, GM Codex가 내 개발용 스킬·설정·저장소 지침을 읽지 않길 원한다. 그래야 GM 컨텍스트가 오염되지 않는다.
17. 호스트로서, GM이 셸 명령이나 파일 쓰기를 못 하길 원한다. 원격 플레이어의 입력이 내 컴퓨터를 건드리면 안 된다.
18. 호스트로서, 방 코드를 모르는 사람은 터널 주소를 알아도 들어와서 내 Codex 사용량을 쓰지 못하길 원한다.
19. 호스트로서, 한 번에 GM 턴이 하나만 돌길 원한다. 그래야 사용량이 폭주하지 않는다.
20. 호스트로서, GM 턴이 실패하거나 너무 오래 걸리면 게임이 멈추지 않고 로그에 알림이 남길 원한다.
21. 호스트로서, 서버 실행과 터널 공개 절차를 문서 하나 보고 따라 하고 싶다.
22. 호스트로서, 나도 캐릭터 하나를 맡아 같이 플레이하고 싶다 (약관 판단의 전제, 대전제 2.4).
23. 섬 제작자로서, 내 `gm.md`가 우리 섬에 있을 때 GM 지침으로 들어가길 원한다 (대전제 9.1).
24. 섬 제작자로서, 섬 장면 코드(`useGameState`, `useMove`, `useSendAction`)를 바꾸지 않아도 GM 연결과 실시간 갱신이 동작하길 원한다.
25. 코어 개발자로서, 실제 Codex 없이 가짜 GM 공급자로 턴 흐름 전체를 테스트하고 싶다.
26. 코어 개발자로서, GM 공급자를 다른 모델로 바꿀 때 턴 흐름 코드를 고치지 않길 원한다 (`GMProvider`, 대전제 2.4).
27. 코어 개발자로서, GM이 호출한 도구와 결과가 로그로 남길 원한다. 그래야 서술과 상태가 어긋났을 때 추적할 수 있다.
28. 코어 개발자로서, GM 도구가 턴이 열려 있을 때만 상태를 바꿀 수 있길 원한다. 그래야 턴 밖에서 도구 엔드포인트가 호출돼도 상태가 바뀌지 않는다.

## Implementation Decisions

### 턴 실행 (GMProvider)

- GM 턴 1회 = `codex exec` 1회. 이어 붙이는 세션(`resume`)이나 상주 `mcp-server`는 쓰지 않는다. 턴마다 엔진이 현재 상태를 새로 넣으므로 GM이 오래된 상태를 믿을 일이 없다.
- `GMProvider` 인터페이스: 턴 입력(프롬프트 계층 + 이번 턴의 행동·이벤트 묶음)을 받아 서술 텍스트를 돌려준다. 상태 변경은 반환값이 아니라 턴 중 도구 호출로만 일어난다.
  - 기본 구현 `CodexCliProvider`: `codex exec`를 자식 프로세스로 실행한다. 마지막 메시지를 서술로 쓴다.
  - 테스트용 `ScriptedProvider`: 정해진 도구 호출과 서술을 흉내 낸다.
- 실행 옵션:
  - 작업 디렉터리: 저장소 밖 `~/.tragic_trpg/gm-workspace/`. 엔진이 턴마다 그 안의 `AGENTS.md`에 프롬프트 계층을 써 넣는다.
  - 샌드박스: 읽기 전용. 세션 파일은 남기지 않는다(ephemeral). git 저장소 검사는 건너뛴다.
  - `CODEX_HOME`: GM 전용 `~/.tragic_trpg/gm-codex`. 호스트가 이 경로로 `codex login`을 한 번 한다(hindsight와 같은 방식). 개발용 스킬(gstack `--host codex` 등)과 개인 MCP 설정이 섞이지 않게 하려는 것이다.
  - MCP: 엔진 도구 서버 하나만 `-c`로 붙인다.
- 제한 시간을 넘기거나 비정상 종료하면 system 로그를 남기고 턴을 닫는다. 이미 적용된 도구 호출은 되돌리지 않는다(도구 로그에 남아 있다).

### 프롬프트 계층 (대전제 9.1)

1. 코어 GM 프롬프트: `/gm`에서 관리한다. 역할, 도구 사용법, 9.2 금지 사항, 출력 형식(서술만)을 담는다.
2. 현재 섬의 `gm.md`: 파티가 있는 섬의 것만 넣는다.
3. 현재 상태: 엔진이 만든다. 파티(캐릭터별 HP·정신력·지점), 위치와 지역 묘사, 이동 가능 목록, 켜진 플래그, 최근 로그 N개.
4. 이번 턴 입력: 캐릭터별 행동과 엔진 이벤트(도착 등).

긴 세션 요약(9.3)은 이번 범위에서 빼고, 최근 로그 N개만 넣는다.

### GM 도구 (MCP)

- MCP 서버는 Next.js 서버 프로세스 안의 HTTP 엔드포인트로 연다. 게임 세션과 같은 메모리를 쓴다.
- 턴마다 일회용 토큰을 만들어 `codex exec`에 넘긴다. 도구 호출은 그 토큰의 턴이 열려 있을 때만 받는다. 엔드포인트는 localhost에서 온 요청만 받는다(터널로 들어온 요청은 거부한다).
- 첫 범위의 도구는 지금 엔진이 가진 기능까지만 연다.
  - `get_state`
  - `move_party(location_id)`, `travel(island_id)`, `move_to_spot(character, spot_id)`: 엔진 이동 함수를 그대로 쓰고, 실패 코드를 GM에 돌려준다.
  - `set_flag`, `get_flag`: ID 접두사 규칙(8.2)을 검사한다.
- `roll_check`, `attack`, HP·아이템 도구는 엔진에 판정·자원 규칙이 생길 때 추가한다(범위 밖).
- 모든 도구 호출과 결과를 턴 로그에 남긴다. 화면에는 system 로그로 요약한다.

### 턴 조율 (방 하나)

- 세션은 지금처럼 서버 메모리에 방 하나를 둔다.
- 입력 큐: 플레이어 행동과 엔진 이벤트(이동 도착)가 큐에 쌓인다. 큐가 비어 있다가 첫 항목이 들어오면 모음 창(기본 4초, 설정 가능)이 시작된다. 창이 닫히면 그동안 쌓인 것을 한 묶음으로 GM 턴에 넘긴다.
- 턴은 한 번에 하나만 돈다. 턴 도중 들어온 입력은 다음 묶음이 된다.
- 명확한 이동(`useMove`)은 큐와 상관없이 엔진이 바로 처리하고 상태를 방송한다. 도착 이벤트만 큐에 넣어 서술을 받는다. 가짜 도착 문장은 없앤다.
- `/move <섬_id>` 같은 개발용 명령은 GM을 거치지 않는다.

### 실시간 갱신

- 서버가 상태 스냅숏을 SSE로 모든 접속자에게 민다. 상태가 바뀔 때(이동, 로그 추가, 턴 시작·종료)마다 보낸다.
- `GameState.pending`은 "GM 턴이 돌고 있거나 모음 창이 열려 있음"을 뜻하게 바꾼다. 지금은 브라우저 요청 대기 중인지를 뜻한다.
- 섬 장면이 쓰는 공개 훅(`useGameState`, `useMove`, `useSendAction`)의 모양은 바꾸지 않는다.

### 방 입장과 신원

- 서버를 시작할 때 방 코드를 만들어 호스트 콘솔에 보여 준다. `.env`로 고정할 수도 있다.
- 입장 화면: 방 코드를 넣고 비어 있는 캐릭터를 고른다. 결과는 서명한 쿠키에 저장한다. 로그인 기능은 없다.
- 행동 로그에 캐릭터를 붙인다. `LogEntry`에 행동한 캐릭터 id를 추가한다.
- 방 코드 쿠키가 없는 요청은 상태 조회, 행동, 이동, SSE 모두 거부한다.

### 호스팅

- 호스트 PC에서 웹 서버를 실행하고 Cloudflare Tunnel이나 Tailscale Funnel로 외부에 연다. Vercel 같은 서버리스 배포는 쓰지 않는다. 메모리 상태와 호스트 `codex` 실행이 필요해서다.
- 호스트도 캐릭터 하나를 맡아 플레이에 참여하는 것을 전제로 한다. 약관 판단의 근거가 이것이다. 근거는 팀 판단이고 약관 원문 확인은 아니다.

## Testing Decisions

- 좋은 테스트는 겉으로 드러나는 동작만 본다. 무엇을 넣었을 때 로그·상태·방송이 어떻게 되는지를 보고, 내부 함수 호출 순서는 보지 않는다.
- 테스트 이음새는 **게임 세션(방)** 하나를 가장 높은 지점으로 둔다. 행동 제출, 이동, 상태 구독을 입력으로 넣고, `ScriptedProvider`와 가짜 시계로 턴 흐름 전체를 검증한다.
  - 묶음: 창 안의 행동 여러 개가 턴 한 번으로 간다.
  - 턴 도중 들어온 입력은 다음 턴으로 간다.
  - 도구 호출이 상태를 바꾸고, 닫힌 턴의 토큰으로 호출하면 거부된다.
  - 실패·시간 초과 턴이 system 로그를 남기고 다음 턴이 정상으로 돈다.
  - 이동 후 도착 이벤트가 서술로 이어진다.
- GM 도구 핸들러는 엔진 순수 함수처럼 따로 테스트한다. 선례는 엔진의 이동·월드 테스트(`npm test`)다.
- 프롬프트 계층 생성은 스냅숏 수준으로 확인한다. 현재 섬의 `gm.md`만 들어가는지, 상태 블록에 필요한 항목이 있는지를 본다.
- `CodexCliProvider`는 자동 테스트하지 않는다. 호스트가 실제 `codex`로 확인하는 수동 점검 목록을 둔다: 로그인, 샌드박스 읽기 전용, MCP 연결, 개발용 스킬이 보이지 않는지.

## Out of Scope

- 판정·전투·HP·아이템 도구(`roll_check`, `attack`, `apply_damage` 등). 엔진 규칙 구현이 먼저다.
- 긴 세션 요약, hindsight 장기 기억 연결
- 저장과 불러오기, 여러 캠페인·여러 방
- 로그인·계정, 관전자 모드
- Vercel 등 서버리스 배포
- 세션당 토큰·비용 한도 수치(9.3 [TBD]). 이번에는 "턴 하나씩 + 모음 창"으로만 제한한다.
- 서술 스트리밍(글자가 흘러나오는 표시). 이번에는 턴이 끝나면 한 번에 붙인다.

## Further Notes

- 약관: "호스트가 직접 참여하므로 계정 공유가 아니다"는 팀 판단이다. 약관 원문을 확인하면 링크를 대전제 2.4에 붙인다.
- 한 턴의 체감 지연은 모음 창 몇 초와 `codex exec` 기동·추론 시간을 더한 것이다. 첫 플레이테스트에서 재어 보고 모음 창 길이를 조정한다.
- 대전제 2.4, 2.5, 9.3과 12장에 이 결정을 [제안]으로 반영했다. [확정]으로 바꾸는 것은 합의 뒤에 한다.
