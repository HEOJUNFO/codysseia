# 03: 명확한 이동 → GM 도착 서술

**What to build:** 이동 버튼이나 장면 지도로 이동하면 엔진이 바로 옮기고, 도착 이벤트(`location_entered`, 첫 방문 여부)를 GM 턴에 넘겨 도착 묘사를 받는다. 섬 간 이동이면 항해 이벤트(`voyage`, 출발·도착 섬, 걸린 시간)도 함께 넘겨 뱃길을 먼저 서술하게 한다 (대전제 8.6 "항해"). `GameRoom`의 가짜 도착·항해 문장(`#arrival`, `#applyEvents`)은 없앤다. 첫 방문은 자세히, 재방문은 짧게 묘사한다. 스펙: `../spec.md` "턴 조율".

**Blocked by:** 01

**Status:** resolved

- [x] 도착 이벤트가 GM 턴 입력에 첫 방문 여부와 함께 들어간다
- [x] 섬 간 이동이면 항해 이벤트가 걸린 시간과 함께 GM 턴 입력에 들어간다
- [x] 방 시작 때의 첫 도착도 같은 경로로 서술된다
- [x] "(가짜 GM)" 도착·항해 문장이 더 이상 나오지 않는다
- [x] `/move <섬_id>` 개발 명령은 GM을 거치지 않는다
- [x] 방 테스트: 이동 → 상태 즉시 변경 → 도착 서술 로그

- 가짜 문장의 위치를 `GameRoom`으로 바꿔 적고, 방 시작 때의 첫 도착 항목을 더했다. 범위는 그대로다.

### 2026-09-27 — 구현

- `GMInput`에 `voyage`(출발·도착 섬 이름, 걸린 시간)와 `arrival`(장소, 첫 방문 여부)을 더했다. GM 큐 항목은 입력 여러 개를 담는 `GMQueueItem`이 되어, 섬 간 이동의 항해와 도착이 한 턴에 함께 들어간다.
- `#move`는 장면 변경분을 먼저 발행하고 도착을 `#queueArrival`로 큐에 넣는다. 섬 진입의 system 로그(`섬 이동 → …`)는 그대로 남긴다. 방 생성자도 같은 경로로 첫 도착을 큐에 넣는다.
- GM이 턴을 도는 동안 파티가 또 움직이면 아직 시작하지 않은 이전 도착은 버리고 그 항해만 새 도착 앞에 잇는다. 큐에 도착 항목은 많아야 하나이므로 GM 턴의 현재 상태와 도착 장소가 어긋나지 않는다. `/move`는 GM 턴을 넣지 않고, 기다리던 도착만 버린다.
- 04(`gmThinking`)와 맞췄다. 도착으로 GM 턴이 시작되면 그 장면 변경분에 `gmThinking: true`를 싣는다(`play.ts` scene 변경분, `provider.tsx` 반영). 생성자의 첫 도착은 스냅숏의 `gmThinking`으로 전해진다.
- 코어 프롬프트에 항해·도착 서술 규칙(뱃길 먼저, 첫 방문 자세히·재방문 1~2문장)을 더했다.
- 확인: `npm test` (방 테스트 6개, 프롬프트 테스트 1개 추가), 엔진 typecheck, `src/web` `tsc --noEmit`.
- 실제 Codex로 도착 서술을 받아 보는 점검은 01의 수동 점검 목록과 함께 호스트가 한다.
