# 섬 플레이 인터페이스 검토

## 현재 구현과 경계

| 관심사 | 단일 원본 | 섬 화면에서 쓰는 인터페이스 |
|---|---|---|
| 위치·HP·정신력·지도 | `src/engine`의 상태와 `src/game/room.ts`의 방 상태 | `useGameState()`, `useMove()` |
| 섬별 공용·캐릭터별 추가 상태 | 방의 `IslandState`와 검증된 패치 이력 | `useGameState().islandState`, `useIslandPlayerState()` |
| 현재 참가자 | 로비 멤버 토큰과 방의 캐릭터 대응 | `usePlayIdentity()` |
| 장면 순서 턴 | `src/game/turn.ts`와 방의 현재 턴 | `useTurnState()`, `useEndTurn()` |
| 섬 전용 판정 | 승인된 `IslandActionHandler`와 방의 명령 큐 | `useIslandAction()` |

섬 `web/`는 2D·3D·텍스트 등 표현 방식을 자유롭게 바꾸되 `@codysseia/play`만 사용한다. `src/catalog/island-catalog.mjs`가 섬 패키지의 플레이 가능 여부를 판단해 호스트와 웹 라우트 생성기에 함께 제공한다. 섬 데이터의 `turn_mode`는 `free`(기본) 또는 `ordered`를 고른다. 순서 턴은 파티 참가 순서로 시작하고 명시적인 종료 명령으로만 전진한다. 호스트는 끊긴 참가자의 차례를 넘길 수 있다. 타이머로 턴 완료를 추측하지 않는다. 섬 행동 핸들러는 턴 시작·전진·종료를 요청할 수 있지만 코어가 캐릭터 ID와 전이 조건을 검증한다.

방이 섬별 확장 상태를 보관하고, 패치는 JSON 경로의 필요한 가지에만 적용한다. 변경은 연속 revision으로 발행되어 누락분을 재전송할 수 있다. 화면은 현재 섬의 공개 공용 상태와 캐릭터별 공개 상태를 받는다. 모든 참가자가 전체 공개 상태를 받으므로 비밀 정보는 넣지 않는다.

## 남은 범위

- 전투의 주사위 선공, 턴당 이동·행동 횟수, HP 판정은 대전제 4.4의 별도 코어 규칙이다. 현재 `ordered`는 장면 차례만 제공한다.
- 캐릭터의 코어 HP·정신력은 아직 방 시작 시 기본값으로 생성된다. 외부 프로필에서 코어 능력치를 불러오는 절차는 별도 설계가 필요하다. 섬별 캐릭터 추가 상태는 `createPlayerState`와 패치로 관리한다.
- 실제 Codex GM 턴 큐와 도구는 `.scratch/gm-connection/`의 별도 작업이다. 현재 서술은 임시 문장이다.
- 방 재시작 후 복원과 갑작스러운 호스트 종료 뒤 자동 이전은 아직 구현되지 않았다. 현재 이력은 방 메모리에만 있다.
- 새 섬 전용 판정 코드는 대전제 8.3 절차로 코어에 등록한다. 데이터·화면만 필요한 섬은 코어 변경 없이 제작할 수 있다.
- 현재 등록된 섬 전용 판정 구현은 없다. `useIslandAction()` 호출은 해당 섬의 코어 핸들러가 등록되기 전까지 오류를 돌려준다.
