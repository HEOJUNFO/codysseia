# 멀티플레이 구조 정리

Status: 구현 초안, 코어 변경은 PR과 팀 전원 합의 전까지 제안

Date: 2026-09-27

## 기존 지침

[AGENTS.md](../../AGENTS.md)와 [대전제](../../docs/00_대전제.md)가 우선이다. 엔진이 상태와 판정의 원본이고 GM은 서술자다. 섬 폴더는 데이터 패키지이며 `web/`은 화면만 담당한다. 섬별 서버 코드를 자동 로드하지 않는다. 새 규칙·도구·효과 타입은 대전제 8.3의 이슈와 코어 검토를 거쳐 등록한다. 이 문서는 [제안]을 [확정]으로 바꾸지 않는다.

섬 제작자가 사용할 화면 API는 [섬 제작 템플릿 12절](../../docs/01_섬_제작_템플릿.md)과 [섬 플레이 인터페이스 검토](../island-play-interface/spec.md)에, 호스트 이전 목표는 [플레이어 호스팅 설계](../player-hosted-multiplayer/spec.md)에 있다.

## 경계

| 위치 | 소유하는 일 | 의존 방향 |
| --- | --- | --- |
| `src/engine/` | 이동·판정·게임 원본 상태 | 외부 UI·전송을 모름 |
| `src/game/` | 방의 명령 순서, 엔진 호출, 공개 상태 투영, 변경 이력, 섬별 확장 상태 | 엔진과 프로토콜만 사용 |
| `src/protocol/` | 직렬화된 명령·상태·변경 계약, 확장 상태의 경로별 갱신 | UI·서버를 모름 |
| `src/host/` | 방 소유권, 참가자, WebSocket 연결, 섬 데이터 로드 | 게임 애플리케이션 호출 |
| `src/web/` | 경로, 화면, WebSocket 클라이언트, 연속 번호 복구 | 공개 프로토콜과 엔진의 읽기 전용 계산 API 사용 |
| `src/islands/<id>/` | YAML·GM 지침·화면·자산 | 섬 화면은 `@codysseia/play`만 사용 |

`src/web/server.mjs`는 Next.js와 호스트를 조립한다. 섬 웹 페이지의 코드가 `src/game/` 또는 `src/engine/`를 직접 import하지 않는다.

## 상태와 전파

1. 호스트의 `GameRoom`이 엔진 원본 상태와 섬별 확장 상태를 보유한다. 확장 상태는 현재 섬의 `shared`와 캐릭터 ID별 `players`로 나누며, 섬을 떠났다 돌아와도 방이 열려 있는 동안 유지한다.
2. 최초 접속에는 현재 공개 상태를 한 번 전송한다. 이후 게임·로비 변경에는 각자 연속 번호를 붙여 호스트 메모리에 전부 보관한다. 일반 이동은 방문·발견 추가분을 전파하고 섬 확장 상태는 변경 경로만 전파한다.
3. 참가자는 번호가 건너뛰면 뒤 번호를 보류하고 빠진 구간을 최대 256개씩 요청한다. 순서가 이어지면 보류한 변경을 적용한다. 복구할 수 없으면 명시적으로 새 상태를 받는다. 준비나 완료를 감지하는 타이머 폴링은 없다.
4. 섬 확장 판정은 코어에 등록된 `IslandActionHandler`가 맡는다. 받은 JSON은 유한 수·깊이·경로·캐릭터를 검증하며 변경 경로의 객체만 복사해 과거 이력을 보존한다. 섬 웹 화면에 임의 상태 쓰기 훅이나 섬 코드 자동 실행 경로를 제공하지 않는다.

## 남은 일

- 현재 로비·게임·모든 이력은 호스트 프로세스 메모리에만 있다. 디스크 저장, 참가자별 전체 이력 복제, 호스트 승계는 아직 없다. 종료 시 상태가 사라진다.
- 실제 GM 도구 연결과 수치·플래그용 코어 API는 별도 설계가 필요하다. 현 행동 로그의 GM 문장은 임시다.
- 섬별 추가 규칙은 대전제 8.3에 따라 코어 등록을 검토해야 한다. `IslandActionHandler`는 그 경계만 마련한 상태이며 현재 등록된 핸들러는 없다.
- 2D·3D·다른 표시 방식은 섬 `web/`에서 선택한다. 표현 방식과 관계없이 공개 상태는 같은 프로토콜로 읽는다.
