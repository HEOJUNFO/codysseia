# 대전제 (System Charter)

> 이 문서는 모든 섬 제작자가 지켜야 하는 **공통 규약**이다.
> 섬은 이 문서 위에서 자유롭게 만들되, 이 문서를 바꾸려면 PR + 전원 합의가 필요하다.
>
> 표기: **[확정]** 합의 완료 · **[제안]** 초안, 합의 필요 · **[TBD]** 미정

---

## 1. 비전

- **한 줄 소개**: 여러 제작자가 각자 만든 섬들을 파티가 자유롭게 탐험하는 디지털 TRPG. GM은 AI 에이전트가 맡는다.
- **형태** [확정]: 코드로 구현하는 디지털 게임
- **GM** [확정]: LLM 에이전트. 호스트가 자기 Codex(ChatGPT) 로그인으로 Codex CLI를 GM으로 돌린다 (2.4)
- **탐험 구조** [확정]: 섬 순서 자유 탐험
- **톤** [TBD]: 전체 공통 톤 (예: 비극적 다크 판타지). 섬마다 톤을 바꿀 수 있는 범위도 함께 정한다.
- **콘텐츠 가이드라인** [TBD]: 허용 수위, 다루지 않을 소재 목록

## 2. 아키텍처 대원칙 [제안]

AI가 GM을 맡는 디지털 게임이므로 **가장 먼저 합의해야 하는 항목**이다.

### 2.1 엔진이 진실, GM은 서술자
| 담당 | 하는 일 |
|---|---|
| **엔진 (코드)** | 주사위, 수치 계산, 규칙 판정, 게임 상태(HP, 인벤토리, 위치, 플래그) 저장 |
| **GM 에이전트 (LLM)** | 상황 묘사, NPC 연기, 플레이어 행동 해석, "어떤 판정이 필요한지" 결정 |

- GM은 게임 상태를 **도구 호출(tool/function calling)로만** 바꿀 수 있다. 서술에서 "체력이 5 줄었다"고 말해도 도구를 호출하지 않으면 실제 상태는 바뀌지 않는다.
- 주사위는 엔진의 RNG가 굴린다. LLM이 숫자를 지어내지 않는다.
- 모든 주사위 결과와 시드는 로그로 남겨 재현할 수 있게 한다.

### 2.2 GM 도구 초안
| 도구 | 설명 |
|---|---|
| `roll_check(character, stat, dc)` | 능력 판정 |
| `attack(attacker, target)` | 공격 판정과 피해 계산 |
| `apply_damage` / `heal` | HP·정신력 변경 |
| `grant_item` / `remove_item` | 아이템 지급·회수 |
| `set_flag` / `get_flag` | 스토리 진행 상태 |
| `move_party(location_id)` | 같은 섬의 연결된 지역으로 파티 이동 (8.6) |
| `travel(island_id)` | 다른 섬으로 파티 이동 (8.6) |
| `move_to_spot(character, spot_id)` | 지역 안 지점으로 캐릭터 이동 (8.6) |
| `start_combat` / `end_combat` | 전투 모드 전환 |
| `trigger_event(event_id)` | 섬에 정의된 이벤트 실행 |

섬 전용 도구가 필요하면 8.3의 확장 절차를 따른다.

### 2.3 섬은 데이터 패키지
- 섬은 **코어 코드를 고치지 않고** 데이터(YAML)와 GM 지침(Markdown)만으로 만든다.
- 데이터는 `/schemas`의 JSON Schema로 검증한다. 검증에 실패한 섬은 병합하지 않는다.
- [제안] 예외로 섬 전용 **웹 페이지**(UI 코드)는 섬 폴더의 `web/`에 둔다 (8.5). 화면만 담당하고 게임 규칙과 상태는 다루지 않는다.

### 2.4 GM 실행 방식과 공급자 추상화
- **[확정] 호스트의 Codex 로그인으로 GM을 돌린다.** 게임을 여는 사람(호스트)이 자기 컴퓨터에서 `codex login`한 공식 Codex CLI를 엔진이 실행해 GM을 맡긴다. OpenAI API 키는 쓰지 않는다.
- 게임 코드는 공식 `codex` 실행 파일만 호출한다. `~/.codex/auth.json`을 읽거나 토큰을 꺼내 직접 API를 호출하지 않는다 (약관 위반 위험).
- [제안] 연결 구조 (설계: `.scratch/gm-connection/spec.md`):
  - **GM 턴 1회 = `codex exec` 1회.** 이어 붙이는 세션이나 상주 `codex mcp-server`는 쓰지 않는다. 턴마다 현재 상태를 새로 넣으므로 GM이 오래된 상태를 믿지 않는다.
  - 엔진이 GM 도구(2.2)를 **MCP 서버**로 연다. 웹 서버 프로세스 안의 HTTP 엔드포인트이고, localhost 요청과 열려 있는 턴의 일회용 토큰만 받는다. GM은 이 도구로만 상태를 바꾼다.
  - 작업 디렉터리는 저장소 밖 전용 폴더(`~/.tragic_trpg/gm-workspace/`)이고, 그 안의 지침 파일에 코어 GM 프롬프트 + 섬 `gm.md` + 현재 상태(9.1)를 엔진이 턴마다 생성해 넣는다.
  - GM 전용 `CODEX_HOME`(`~/.tragic_trpg/gm-codex`)을 쓴다. 호스트는 이 경로로 `codex login`을 한 번 더 한다. 개발용 스킬과 개인 설정이 GM에 섞이지 않게 하려는 것이다.
  - GM에는 셸·파일 쓰기 권한이 필요 없으므로 읽기 전용 샌드박스로 실행한다.
  - GM의 마지막 응답을 서술로 쓴다.
- GM은 `GMProvider` 인터페이스 뒤에 둔다. 기본 구현은 Codex CLI이고, 나중에 다른 모델로 교체할 수 있게 한다.
- 주의: 비용은 호스트의 구독 사용량 한도 안에서 쓰인다.
- [제안] 원격 멀티플레이(2.5)는 **호스트가 캐릭터 하나를 맡아 직접 플레이에 참여**하는 것을 전제로 한다. 호스트가 자기 게임에 친구를 초대하는 것이므로 계정 공유가 아니라고 팀이 판단했다. 이것은 팀 판단이고 약관 원문을 확인한 것은 아니다. 원문을 확인하면 여기에 링크를 붙인다.
- 비밀값이 생기면 `.env`에만 두고 절대 커밋하지 않는다.

### 2.5 미결정
- 클라이언트 형태 [제안]: 웹. Next.js(App Router) + TypeScript, 앱은 `/web`
- 엔진 [제안]: TypeScript, `/engine` (npm 워크스페이스, 빌드 없이 소스를 Node·Next.js가 바로 실행)
- GM 연결 방식 [제안]: 2.4 연결 구조
- 멀티플레이 방식 [제안]: **원격 동시 접속**
  - 호스트 PC에서 웹 서버(엔진·GM 포함)를 실행하고 터널(Cloudflare Tunnel, Tailscale Funnel 등)로 외부에 연다. 서버리스 배포(Vercel 등)는 쓰지 않는다. 게임 상태가 서버 메모리에 있고 GM이 호스트의 `codex`로 돌기 때문이다.
  - 접속자는 방 코드를 넣고 캐릭터를 골라 들어온다. 로그인은 없다. 방 코드가 없으면 들어올 수 없다.
  - 상태는 서버가 모든 접속자에게 실시간으로 민다.
  - 행동 처리 방식은 9.3을 따른다.
- 파티 인원 [제안: 1~4명]

## 4. 코어 룰 [제안]

### 4.1 판정
**d20 + 능력치 보정 + 숙련 보너스 ≥ 난이도(DC)**

| 결과 | 조건 |
|---|---|
| 대성공 | 주사위 20, 또는 DC보다 10 이상 높음 |
| 성공 | DC 이상 |
| 실패 | DC 미만 |
| 대실패 | 주사위 1, 또는 DC보다 10 이상 낮음 |

난이도: 쉬움 10 · 보통 13 · 어려움 16 · 매우 어려움 19

### 4.2 능력치 (6종)
힘 · 민첩 · 체력 · 지성 · 감각 · 의지

- 능력치 보정은 -1 ~ +4
- 숙련 보너스: 레벨 1~3 +2 · 4~6 +3 · 7~9 +4 · 10 +5

### 4.3 자원
- **HP**: 0이 되면 쓰러짐
- **정신력**: 공포, 광기, 비극적 사건으로 줄어든다. 0이 되면 섬별 "붕괴" 효과 [TBD: 톤과 함께 결정]

### 4.4 전투
- 선공 순서: d20 + 민첩 보정
- 턴당 이동 1회 + 행동 1회
- 공격: d20 + 보정 ≥ 대상 방어도(AC)

### 4.5 쓰러짐과 사망
- HP 0 → 쓰러짐. 자기 턴마다 d20 ≥ 10 판정, 3번 성공하면 안정, 3번 실패하면 사망
- 사망이 영구적인지 [TBD]

### 4.6 휴식
- 짧은 휴식: 어디서나, HP 절반 회복
- 긴 휴식: 허브나 섬에 지정된 안전지대에서만, 전부 회복

## 6. 밸런스 기준표 [제안, 플레이테스트로 조정]

### 6.1 자유 탐험 스케일링
섬 순서가 자유이므로 **몬스터 수치는 섬 제작자가 직접 쓰지 않는다.**
섬은 몬스터의 **등급**만 정하고, 엔진이 파티 평균 레벨(L)로 수치를 계산한다.

| 등급 | HP | 공격 보정 | 피해 | AC |
|---|---|---|---|---|
| 잡몹 | 4 + 2L | +2 + L/2 | 1d6 + L/2 | 11 + L/3 |
| 일반 | 8 + 5L | +3 + L/2 | 1d8 + L/2 | 12 + L/3 |
| 정예 | 15 + 8L | +4 + L/2 | 2d6 + L/2 | 13 + L/3 |
| 보스 | (30 + 15L) × 인원/4 | +5 + L/2 | 2d8 + L | 14 + L/3 |

- 나눗셈은 내림
- 섬 제작자는 몬스터별로 ±20% 안에서 조정할 수 있다 (예: "HP 높고 AC 낮음")

### 6.2 캐릭터 HP
10 + 체력 보정 + (레벨 - 1) × (6 + 체력 보정)

## 8. 섬 제작 규약

### 8.1 필수 제출물
[`01_섬_제작_템플릿.md`](./01_섬_제작_템플릿.md)를 따른다.

### 8.2 식별자 규칙
- 섬 ID: `snake_case` 영문 (예: `ash_harbor`)
- 모든 ID에는 섬 ID를 접두사로 붙인다: `ash_harbor.npc.old_keeper`
- 스토리 플래그도 같다: `ash_harbor.flag.bell_rung`
- 다른 섬의 플래그는 **읽기만** 할 수 있고, 그 섬이 공개 훅으로 지정한 것만 읽을 수 있다.

### 8.3 코어 확장 절차
섬 전용 도구, 효과 타입, 규칙이 필요할 때:
1. 이슈로 제안한다 (무엇이, 왜 필요한지)
2. 코어 담당자가 검토한다
3. 다른 섬에서도 쓸 수 있으면 코어에 추가, 아니면 섬 전용 확장으로 등록한다

### 8.4 섬 간 연결
- 각 섬은 **공개 훅**을 정의할 수 있다: 다른 섬이 참조해도 되는 NPC, 사건, 플래그
- 메인 플롯 연결 방식 [TBD]. 예: 각 섬이 "파편" 하나를 제공하고, N개를 모으면 최종장이 열린다.

### 8.5 섬 웹 페이지 [제안]
- 섬마다 전용 페이지 경로가 있다: `/islands/<섬_id>`. 파티가 그 섬에 있는 동안의 **플레이 화면**이다.
- 화면 분담:
  - **코어 틀** (`/web`): GM 대화 로그, 행동 입력, 파티 상태(HP·정신력·인벤토리). 모든 섬에서 같은 위치, 같은 조작.
  - **섬 장면 영역** (`islands/<섬_id>/web/`): 배경, 지도, 연출. 제작자가 자유롭게 개발한다.
- **플레이 조건**: 아래가 모두 있어야 플레이할 수 있다. 하나라도 없으면 섬 목록에 '준비 중'으로만 나오고 들어갈 수 없다(`/islands/<섬_id>`는 404, `move_party`도 거부).
  - `island.yaml`, `gm.md`, `locations/`의 지역 파일 1개 이상, `web/page.tsx`(전용 장면)
  - `island.yaml`과 `locations/`는 엔진이 `/schemas` 스키마와 섬 안 참조(ID 접두사, 없는 지역을 가리키는 연결 등)까지 검증한다. 오류가 있으면 섬 목록에 오류 내용이 나온다.
- 파티가 다른 섬으로 이동하면(`move_party`) 화면도 `/islands/<새_섬_id>`로 이동한다. 허브는 `/islands/hub`.
- 장면 영역에서 일어난 조작(지도 클릭 등)은 **행동 요청**으로 GM·엔진에 보낸다. 장면이 상태를 직접 바꾸거나 서술을 지어내지 않는다.
- 장면 영역이 쓰는 API는 `@codysseia/play`의 `useGameState()`(읽기 전용 상태), `useMove()`(이동, 8.6), `useSendAction()`(그 밖의 행동)이다. 상태는 엔진이 주고, GM 서술은 아직 가짜 문장이다 (GM 연결 설계: 2.4, 9.3).
- 코드는 `islands/<섬_id>/web/`에 둔다. 이 폴더는 `/islands/<섬_id>` 아래에 붙는 Next.js App Router 폴더처럼 동작한다.
  - `web/page.tsx` → `/islands/<섬_id>`, `web/map/page.tsx` → `/islands/<섬_id>/map`
  - 쓸 수 있는 파일: `page`, `layout`, `loading`, `error`, `not-found`, `template`. 그 밖의 파일(컴포넌트 등)은 자유롭게 둔다.
  - API 라우트(`route.ts`)는 쓸 수 없다.
- 섬 페이지는 **화면만** 담당한다 (2.1). 주사위·수치·상태 변경은 엔진 API로만 한다. 엔진 API는 [TBD].
- 다른 섬의 `web/` 코드를 import 하지 않는다. 공용 컴포넌트가 필요하면 `/web`에 추가를 제안한다 (8.3).
- 새 npm 패키지가 필요하면 `/web/package.json` 변경이므로 코어 담당자와 합의한다.

### 8.6 이동 [제안]
세 단계로 나눈다. 섬 안의 연결은 같은 섬 안에서만 쓰고, 섬 사이는 섬 이동으로만 오간다.

| 단계 | 단위 | 규칙 |
|---|---|---|
| 섬 간 | 파티 전체 | 현재 섬의 **출발 지역**(`departure_locations`, 없으면 `entry_location`)에서만 떠날 수 있다. 도착하는 곳은 대상 섬의 `entry_location`이다. 대상 섬의 `entry_requires_flags`가 모두 켜져 있어야 한다. 플레이 가능한 섬(8.5)으로만 갈 수 있다. |
| 지역 간 | 파티 전체 | 현재 지역의 `connections`를 따라서만 간다. 한쪽에만 적으면 일방통행이다. `requires_flags`가 꺼져 있으면 보이지만 잠겨 있고, `hidden_until_flags`가 꺼져 있으면 보이지 않는다. |
| 지역 안 | 캐릭터마다 | 지역의 이름 붙은 **지점**(`spots`) 사이를 움직인다. 지역을 옮기면 지점은 초기화된다. |

- **이동 주체**: 이동 버튼, 장면 지도 같은 명확한 이동은 엔진이 조건을 판정해 바로 옮기고, GM은 도착을 묘사한다. "몰래 시장으로 간다"처럼 판정이 필요한 이동은 행동으로 GM에게 보내고, GM이 도구(2.2)로 옮긴다.
- **전투 중**: 섬·지역 이동은 불가, 지점 이동만 가능. 턴당 이동 횟수(4.4)는 전투 구현 때 붙인다.
- **발견**: 방문한 지역과 그곳에서 보이는 연결 지역이 지도에 드러난다 (`discovered`). 장면은 이걸로 지도를 밝힌다.
- **URL**: 화면 주소는 섬 단위(`/islands/<섬_id>`)까지만 쓴다. 지역·지점은 엔진 상태로만 두어 주소창 조작으로 이동할 수 없게 한다.
- 허브를 반드시 거쳐야 하는지는 [TBD]. 지금은 출발 지역에서 모든 플레이 가능한 섬으로 갈 수 있다.
- 지역 진입으로 섬 이벤트를 발동하는 형식(`events`의 `trigger`)은 [TBD]. 엔진은 도착 이벤트(`location_entered`, 첫 방문 여부)를 낸다.

## 9. GM 에이전트 규약 [제안]

### 9.1 프롬프트 계층
1. **코어 GM 프롬프트**: 역할, 규칙, 도구 사용법, 금지 사항 (코어 팀 관리)
2. **섬 GM 지침**: 해당 섬의 톤, 비밀, 진행 가이드 (`gm.md`, 섬 제작자 관리)
3. **현재 상태**: 파티 정보, 위치, 플래그, 최근 세션 요약 (엔진이 자동 생성)

### 9.2 GM이 할 수 없는 것
- 도구를 거치지 않고 수치나 상태를 바꾸기
- 주사위 결과를 지어내거나 무시하기
- 플레이어 캐릭터의 행동이나 대사를 대신 결정하기
- 섬 GM 지침에서 "비밀"로 지정한 정보를 조건 없이 공개하기

### 9.3 운영
- [제안] **턴 조율**:
  - GM 턴은 한 번에 하나만 돈다.
  - 플레이어 행동과 엔진 이벤트(이동 도착 등)는 큐에 쌓인다. 첫 입력 뒤 몇 초(기본 4초) 동안 모은 것을 한 묶음으로 GM 턴 한 번에 넘긴다. 턴 도중 들어온 입력은 다음 묶음이 된다.
  - 명확한 이동(8.6)은 큐를 기다리지 않고 엔진이 바로 처리한다. 도착 이벤트만 큐에 넣어 서술을 받는다.
- [제안] GM 턴이 제한 시간을 넘기거나 실패하면 system 로그를 남기고 턴을 닫는다. 이미 적용된 도구 호출은 되돌리지 않는다.
- GM이 호출한 도구와 결과는 모두 로그로 남긴다.
- 긴 세션은 주기적으로 요약해 컨텍스트를 줄인다. 그 전까지는 최근 로그 몇 개만 넣는다.
- 세션당 토큰·비용 한도 [TBD]. 지금은 "턴 하나씩 + 모음 창"으로만 제한한다.
