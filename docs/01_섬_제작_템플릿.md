# 섬 제작 템플릿

> 이 파일을 `/islands/<섬_id>/README.md`로 복사해서 채운다.
> 규칙은 [`00_대전제.md`](./00_대전제.md)를 따른다.

---

## 1. 기본 정보

```yaml
# islands/<섬_id>/island.yaml
id: ash_harbor                 # snake_case 영문, 모든 ID의 접두사
name: 잿빛 항구
author: 제작자 이름
concept: 한두 문장으로 섬의 컨셉
tone: 섬의 분위기 (대전제 가이드라인 범위 안)
recommended_level: 1-4         # 권장 레벨 (수치는 엔진이 스케일링)
expected_sessions: 2           # 예상 세션 수
safe_zones: [ash_harbor.loc.lighthouse]   # 긴 휴식 가능 장소
entry_location: ash_harbor.loc.docks      # 필수. 다른 섬에서 오면 도착하는 지역
departure_locations: [ash_harbor.loc.docks]   # 선택. 섬을 떠날 수 있는 지역 (없으면 entry_location)
entry_requires_flags: []                  # 선택. 들어오려면 켜져 있어야 하는 플래그
archipelago_position: { x: 25, y: 40 }    # 필수. 군도 지도 위 위치 (0~100 퍼센트, 원하는 곳을 고른다)
map_image: assets/map.png                 # 선택. 섬 지도 배경
```

스키마: [`schemas/island.schema.json`](../schemas/island.schema.json)

## 2. 컨셉과 이야기

- **첫인상**: 파티가 섬에 도착했을 때 보고 듣는 것
- **섬의 비극 / 갈등**: 이 섬에서 무슨 일이 벌어지고 있는가
- **주요 목표**: 무엇을 달성하면 섬을 "클리어"한 것인가 (마일스톤 레벨업 기준)
- **결말 분기**: 선택에 따라 섬이 어떻게 달라지는가

## 3. 진입과 탈출

- 섬에 들어오는 조건 (없으면 "자유") → 엔진이 판정할 조건은 `entry_requires_flags`에 적는다
- 도착 지역 → `entry_location`, 떠날 수 있는 지역 → `departure_locations`
- 도중에 떠나면 어떻게 되는가 (GM 지침에 적는다)

## 4. 지역

```yaml
# islands/<섬_id>/locations/*.yaml
id: ash_harbor.loc.market
name: 무너진 시장
description: GM이 묘사에 참고할 설명
map_position: { x: 50, y: 45 }           # 선택. 섬 지도(map_image) 위 위치
image: assets/market.jpg                 # 선택. 현장 뷰 배경
spots:                                   # 선택. 지역 안 지점 (캐릭터마다 따로 선다)
  - { id: ash_harbor.spot.stall, name: 부서진 노점, position: { x: 25, y: 60 } }   # position: 현장 뷰 위 위치
  - { id: ash_harbor.spot.well, name: 마른 우물 }
connections:                             # 같은 섬 안의 지역만. 한쪽에만 적으면 일방통행
  - ash_harbor.loc.docks                 # 항상 갈 수 있음
  - to: ash_harbor.loc.lighthouse
    requires_flags: [ash_harbor.flag.key_found]      # 꺼져 있으면 '잠김'으로 보인다
  - to: ash_harbor.loc.cellar
    hidden_until_flags: [ash_harbor.flag.map_read]   # 꺼져 있으면 보이지도 않는다
events: [ash_harbor.event.market_ambush]
```

스키마: [`schemas/location.schema.json`](../schemas/location.schema.json). 이동 규칙은 대전제 8.6, 지도는 8.7.

좌표는 모두 이미지 왼쪽 위 (0,0) ~ 오른쪽 아래 (100,100)인 퍼센트다. 이미지는 `islands/<섬_id>/assets/`에 둔다.

## 6. 몬스터

수치는 쓰지 않는다. **등급**만 정하면 엔진이 파티 레벨로 계산한다.

```yaml
# islands/<섬_id>/monsters/*.yaml
id: ash_harbor.mon.drowned
name: 익사자
tier: 일반                      # 잡몹 | 일반 | 정예 | 보스
adjust: { hp: +20%, ac: -10% }  # 선택, 항목별 ±20% 이내
traits: [물속에서 유리]
description: 외형과 행동 패턴
```

## 7. 아이템

```yaml
# islands/<섬_id>/items/*.yaml
id: ash_harbor.item.bell_shard
name: 종의 파편
grade: 희귀                     # 일반 | 고급 | 희귀 | 전설
effects:
  - { type: resist, value: 정신력 피해 -1 }
island_bound: false            # true면 섬 밖에서 효과 없음
```

희귀 최대 3개, 전설 최대 1개.

## 9. 섬 전용 규칙 (선택)

- 규칙 설명
- 섬을 떠나면 효과가 유지되는가
- 코어에 새 도구나 효과 타입이 필요하면 대전제 8.3 절차로 요청

```yaml
  - "동쪽 항구의 종이 다시 울렸다는 소문"
```

## 11. GM 지침 (`gm.md`)

섬을 진행하는 GM 에이전트에게 주는 지침.
- 묘사 스타일, 강조할 감각 (소리, 냄새 등)
- 비밀과 공개 조건
- 파티가 막혔을 때 줄 힌트
- 하지 말아야 할 것

## 12. 섬 웹 페이지 (필수)

섬에 있는 동안의 플레이 화면 중 **장면 영역**(배경, 지도, 연출)을 직접 만든다. `islands/<섬_id>/web/`에 Next.js App Router 파일을 둔다. 규칙은 대전제 8.5를 따른다.

- GM 대화창, 행동 입력, 파티 상태창은 코어 틀이 항상 그려준다. 섬 페이지에서 따로 만들지 않는다.
- `web/page.tsx`가 없으면 플레이할 수 없다. `island.yaml`, `gm.md`, `locations/` 지역 1개 이상도 있어야 한다 (대전제 8.5 플레이 조건). 모자라면 섬 목록에 '준비 중'과 빠진 항목이 나온다.
- 장면은 장면 영역을 꽉 채우게 만든다 (`h-full`).
- 가장 간단한 장면은 코어의 현장 뷰를 그대로 쓰는 것이다. 지역 YAML의 `image`와 지점 `position`만 채우면 된다.

```tsx
"use client";
import { LocationView } from "@codysseia/play";

export default function Scene() {
  return <LocationView />;
}
```

- 직접 그리고 싶으면 `@codysseia/play`의 훅으로 상태를 받는다. 훅은 `"use client"` 파일에서만 쓸 수 있다. `IslandMap`, `LocationView`는 `image`를 바꿔 끼울 수 있다.

```tsx
"use client";
import { useGameState, useMove, useSendAction } from "@codysseia/play";

export default function Scene() {
  const { place, moves, discovered } = useGameState();   // 읽기 전용
  const move = useMove();                                // 이동은 엔진이 판정해 바로 처리
  const send = useSendAction();                          // 그 밖의 행동은 GM에게
  return (
    <>
      {moves.locations.map((l) => (
        <button key={l.id} disabled={l.locked} onClick={() => move.toLocation(l.id)}>{l.name}</button>
      ))}
      <button onClick={() => send("우물을 들여다본다")}>우물</button>
    </>
  );
}
```

```
islands/<섬_id>/web/
  page.tsx            → /islands/<섬_id>
  layout.tsx          → 섬 페이지 공통 레이아웃 (선택)
  map/page.tsx        → /islands/<섬_id>/map
  components/         → 자유
islands/<섬_id>/assets/
  map.png             → /islands/<섬_id>/assets/map.png (YAML에는 assets/map.png)
```

- 섬이나 라우트 파일(`page.tsx` 등)을 새로 만들거나 지웠으면 `npm run sync:islands -w web`를 실행한다. 내용만 고칠 때는 필요 없다 (`npm run dev`가 시작할 때도 자동 실행).
- 확인: 저장소 루트에서 `npm install` → `npm run dev` → `http://localhost:3000/islands/<섬_id>`

## 병합 전 체크리스트

- [ ] 모든 ID에 섬 ID 접두사가 붙어 있다
- [ ] 스키마 검증을 통과했다 (섬 목록에서 '준비 중'이 아니다)
- [ ] 몬스터에 직접 수치를 쓰지 않았다 (`adjust`는 ±20% 이내)
- [ ] 희귀·전설 아이템 한도를 지켰다
- [ ] 다른 섬의 비공개 플래그나 설정을 참조하지 않았다
- [ ] 코어 룰을 수정하지 않았다 (확장은 8.3 절차로 승인받음)
- [ ] 긴 휴식 가능한 안전지대가 최소 1곳 있다
- [ ] 다른 사람이 한 번 플레이테스트했다
- [ ] `npm run build`가 통과하고, 페이지가 게임 상태를 직접 바꾸지 않는다
