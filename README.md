# 코디세이아 (Codysseia)

여러 제작자가 각자 만든 섬을 파티가 자유롭게 탐험하는 디지털 TRPG.
GM은 호스트의 Codex가 맡는다.

> 이름은 『오디세이아』에서 친구 별명 "코"를 따왔다.

## 시작하기

- 공통 규약: [`docs/00_대전제.md`](docs/00_대전제.md)
- 섬 만들기: [`docs/01_섬_제작_템플릿.md`](docs/01_섬_제작_템플릿.md)
- 개발 환경과 에이전트 지침: [`AGENTS.md`](AGENTS.md)
- 참고 저장소: [`docs/references.md`](docs/references.md)

개발 작업은 [AGENTS.md의 작업별 문서 읽기](AGENTS.md#작업별-문서-읽기)에서 해당 경로를 따라간다. `.scratch/`의 설계 문서는 구현 범위와 미완료 사항을 기록하며, 공통 규약의 승인 상태는 대전제가 정한다.

## 웹 실행

게임 코드와 섬 데이터는 `src/` 아래에 있다: `src/engine`, `src/game`, `src/gm`, `src/protocol`, `src/host`, `src/web`, `src/islands`, `src/schemas`. 프로젝트 지침과 문서는 루트의 `AGENTS.md`, `docs/`에 둔다.

```sh
npm install
npm run dev   # http://localhost:3000, 섬 페이지는 /islands/<섬_id>
npm test      # 엔진·방·GM 테스트 (Node 22.18 이상)
```

## GM 준비 (호스트만, 한 번)

행동 입력은 호스트 PC의 공식 `codex` CLI가 GM으로 서술한다. 개발용 Codex 설정과 섞이지 않게 GM 전용 로그인을 한 번 한다.

```sh
mkdir -p ~/.tragic_trpg/gm-codex
CODEX_HOME=~/.tragic_trpg/gm-codex codex login
```

로그인하지 않으면 게임은 그대로 돌고, 행동마다 "GM 서술을 받지 못했습니다" system 로그가 남는다. 경로·제한 시간 설정과 수동 점검 목록은 [`src/gm/README.md`](src/gm/README.md)에 있다.

## 멀티플레이 로비

`npm run dev` 또는 `npm run build && npm start`를 실행하면 Next 화면과 방 WebSocket이 한 프로세스에서 열린다. 기본 포트는 3000이다.

1. 호스트가 자기 컴퓨터의 `http://localhost:3000/rooms/new`에서 방을 연다. 같은 컴퓨터의 LAN IP로 접속해도 방을 만들 수 있으며, 다른 기기에서는 방 만들기 메뉴에 호스트 PC에서만 가능하다고 표시된다. 같은 호스트에서 방을 여러 개 열 수 있다.
2. 대기실에 표시된 내부 IP 주소와 8자리 방 코드를 같은 네트워크의 친구에게 전달한다.
3. 참가자는 `/rooms/join`에서 호스트 IP:포트, 방 코드, 이름을 입력한다. 다른 네트워크라면 호스트의 공개 IP:포트 또는 터널 주소를 사용한다. 공개 IP 접속에는 호스트의 방화벽과 공유기에서 해당 포트로 접근할 수 있어야 한다.
4. 대기실에서 접속자, 빈 자리, 준비 상태가 WebSocket으로 갱신된다. 호스트는 참가자를 내보내거나 방을 닫을 수 있다.
5. 참가자가 준비하면 호스트가 게임을 시작한다. 모두 `/explore`의 군도 지도로 이동하고 현재 섬의 장면으로 들어갈 수 있다. 메인 화면 `/`도 군도 지도이며, 방에 들어간 상태라면 파티 위치를 보여준다. 호스트는 파티의 지역·섬 이동을, 각 참가자는 자기 캐릭터의 지점 이동을 결정한다.

자동 방 탐색과 중앙 방 목록은 없다. 참가자는 같은 네트워크에서도 호스트 IP 주소를 직접 입력한다. 접속한 호스트의 `/rooms`에는 그 호스트가 연 방들이 보인다. 초대 링크로 들어오면 해당 호스트 주소와 방 ID가 참가 화면에 채워진다. 브라우저의 참가 자격은 방별로 유지된다.

개발 서버는 실행 시 호스트 컴퓨터의 LAN IP를 Next.js 개발 리소스 허용 목록에 넣는다. 공개 IP나 별도 도메인으로 개발 서버에 접속한다면 `CODYSSEIA_ALLOWED_DEV_ORIGINS`에 그 IP 또는 도메인을 쉼표로 구분해 지정한 뒤 서버를 다시 켠다. 배포 실행(`npm run build && npm start`)에는 이 개발용 설정이 필요 없다.

각 방은 독립된 엔진 상태와 연속 번호가 붙은 변경 이력을 소유한다. 새로 연결한 참가자는 현재 상태를 받고, 연결이 끊겼다 돌아온 참가자는 빠진 번호의 변경만 재전송받아 순서대로 적용한다. `src/game/room.ts`는 게임 규칙과 상태를, `src/host/lobby.mjs`는 방과 연결을, `src/web/lib/play/provider.tsx`는 클라이언트 동기화를 담당한다. 화면과 섬 장면은 `@codysseia/play` 훅으로만 게임 상태를 읽고 명령을 보낸다.

섬 화면은 2D·3D 등 자유롭게 구성할 수 있지만 게임 판정이나 상태 변경은 코어 API가 맡는다. 게임 상태에는 섬별 공유·캐릭터별 확장 데이터를 담을 자리가 있고, 변경은 엔진 경계에서 검증해 변경 이력으로 전파한다. 섬 전용 규칙을 붙이려면 [대전제 8.3](docs/00_대전제.md)의 코어 확장 절차가 먼저 필요하다. 현재 경계와 남은 작업은 [아키텍처 정리 기록](.scratch/architecture-cleanup/spec.md)에 적었다.

현재 방·게임 상태·변경 이력은 호스트 프로세스 메모리에 있다. 디스크 저장, 다른 참가자로의 상태 복제와 호스트 이전은 아직 구현되지 않았다. 행동 입력은 Codex GM이 서술하지만 GM 도구(상태 변경)는 아직 없고, 도착·항해 서술은 임시 문장이다.
